# 论文叙事核心(引言 + 系统章骨架;措辞纪律清单)

冻结日期:2026-07-07。本文档是引言与系统章的骨架依据;与 abstract_variants.md、
results_master_table.md 三件套构成写作的单一事实源。

## 一句话论文(引言用)

> **中文**:他管不到的地方,可以用他管得到的地方的结果进行学习。
> **英文(引言原句)**:*Supervision flows only from the verifiable region, yet the learned
> competence extends beyond it.*

证据:hard-composite 切片上教师衰减 6–12pt、fully-local 学生 +0.8pt(n=136,模式措辞);
训练信号 100% 来自验证器放行 + oracle 把关的可验证区(oracle 只把关、从不代笔)。
这是 "partial (verifiability) is enough" 的机制答案:**学到的能力比信号的覆盖面宽。**

## 三层结构(系统章总纲)

1. **硬验证层**:语义判断链上每一个**能被投影到结构/执行层面的性质**,都被确定性检查钉死。
2. **弃答层**:投影不到的残余(纯语义对应)构成盲区;盲区由弃答接住(三类弃答陷阱
   是这一层的完备性测试,不是基准装饰)。
3. **学习层**:可验证区流出的信号驱动蒸馏/自举;学到的能力反过来覆盖盲区一部分(一句话论文)。

## 检查链的精确表述(四道,标注硬/缝)

| # | 对应关系 | 性质 |
|---|---|---|
| 1 | executor ↔ plan graph | **硬**(编译执行,确定性) |
| 2 | plan graph ↔ briefing | **硬**(结构比对,代码层) |
| 3 | briefing ↔ question | **缝**:代码只能查投影(槽位、实体、字面量、数字、角色、cue 词),
查不了"意思对不对"——**盲区入口,hard negatives 全部由此漏入** |
| 4 | (训练期)answer ↔ oracle | 硬,但只在训练期存在;评测期不进管线(进了就是作弊) |

**禁写**:"确定性检测一切/检测不确定性"。
**应写**:"能硬的全部硬掉,不能硬的压缩到最小,然后用弃答和学习去接。四道检查是把盲区
一层层挤小的过程,不是消灭盲区的过程。"

## 投影边界是可移动的(动态原理;本项目的实时实证)

盲区不是固定集合:**工程努力 = 把语义性质搬过投影线**。实证:v2 修复把"count-intermediate-set"
从纯语义错误投影为结构性质(return 指向 entity_set 的 record-count 问题→代码可查),
"empty-value lookup"与"unsupported-cue"同理;v1→v2 全档 +5pt 左右即投影线移动一次的度量
(v2.1/v2.2 迭代同时表明:投影过度会误伤——alias 覆盖率事故——移动边界需要真实中间产物回归)。
搬不动的才留给弃答与学习。

## Reflector 的位置(严格措辞)

Reflector **不是第五道验证**。它是**验证信号的消费者**:四道硬检查产生诊断信号,reflector
(LLM,不确定)拿信号修计划,其输出**再过同样四道检查**(门控修复;v1/v2 消融中的增益来源之一)。

**禁写**:把 reflector 称为 verifier/验证者(审稿人会问"reflector 错了谁管",拖入 PRM 死循环叙事)。
**应写**:verifier 产生信号(确定性),reflector 消费信号(不确定,但被门控)。本架构的设计
初衷正是不进入"用不确定模型验证不确定模型"的循环。

## 与四支柱的挂接

- 支柱 1(自举闭环)= 学习层的三次实例化(教师过滤 / 自收割反超 / Step-1 去噪蒸馏)
- 支柱 2(增益分解)= 硬验证层与学习层的贡献分离
- 支柱 3(DPO 毒性)= 学习层里"减法压制 vs 加法蒸馏"的对照
- 支柱 4(基准方法学)= 弃答层的测试装置 + 全部数字的可信度地基
