# Chapter 11 — Portability: The Recipe on Foreign Tables

Every result so far lives on one knowledge graph. This chapter transplants the system to WikiTableQuestions — 22,033 crowd-written questions over 2,108 heterogeneous web tables, with a sealed test set and an official evaluator — and asks three questions in a fixed order. What must change for the system to run at all? Given gold programs, how much of the benchmark can the algebra express, and how well does the stack execute what it expresses? And when supervision is restricted to final answers alone — the regime the thesis has argued for throughout — how close does bootstrapped training come to the gold-program ceiling?

## 11.1 What had to change: the migration inventory

The core did not. All seventeen original operators, the type checker, and the runtime evaluator transferred unchanged; one generic operator was added (`extreme_rows`, row-preserving arg-extremum — a relational capability the procurement KG never needed but half of WTQ's most common idiom requires), motivated by a train-split census and tagged as the boundary between an adapter-only baseline and the extended algebra. What is genuinely new is representation: a table loader that parses the official TSVs deterministically (2,108/2,108 tables, row conservation asserted, zero silently dropped rows — the naive CSV path had been silently corrupting 81 tables), maintains a dual view (typed columns for computation, raw display strings for answers), and materialises typed derived views under fixed cross-split rules — the k-th numeric token in text order, minimum and maximum four-digit years; ambiguous "first/second component" splits were considered and rejected because their semantics vary per cell. A column-aware value linker — the table analogue of the production entity resolver — retrieves candidate cells per column into the prompt under locked rules (current table only, fixed top-k, never conditioned on gold data). A four-condition ablation validated it before adoption: cells +4.0 points over the dynamic-schema baseline (McNemar p = 0.0075), ranked columns alone +1.3, and a random-cell control *negative* — the gain is grounding, not context length.

Squall's 11,276 gold SQL annotations enable the expressibility layer. A leak audit before anything else: zero overlap, at table and question level, between Squall and the WTQ test split; a table-disjoint train/dev fold was adopted, and the test split's annotations were never read. A translator lowers gold SQL into the algebra, grounding lowercase-normalised literals back to raw cell values; a differential audit executes reference SQL on Squall's own SQLite tables and the translated tree on our stack, separating three numbers that a single accuracy would blur: **syntactic coverage** (initially 54.7% train / 52.7% dev), **translation fidelity** 92–93%, and **executor accuracy on correctly-translated programs** 94.1% — against an 88.9% ceiling set by annotation and normalisation noise itself. The stack executes what it can express nearly as well as the gold annotations allow; the binding constraint is coverage.

## 11.2 The supervision ladder

All internal comparisons run on a 300-question set whose tables are disjoint from every training pool. Zero-shot floors: the untrained base 15.3%, the procurement-trained planner 15.7% — statistically indistinguishable at this sample size (p = 0.56), though their behaviour differs (the trained planner abstains a third as often and truncates three times as often). Learning curves from both initialisations *overlap* within ±2 points at every mark from 100 to 2,000 steps, and 100 steps (~1,600 examples) already lifts either model to 37%: sample efficiency is extreme, the plateau is a data-coverage property, and procurement *weights* buy no measurable adaptation speed.

Three supervised arms, identical recipe, different supervision: **A**, denotation-only bootstrap — the planner samples eight trees per question at temperature 1.0 and keeps those whose executed answer matches the gold answer, no program supervision anywhere — trains to **31.67%**, essentially reaching the 32.7% gold-translation ceiling of its evaluation set. **B**, the same pool filtered to trees whose shape matches the gold program, ties A (30.0%, p = 0.49) with a third of the data: spurious programs are *not* what separates bootstrap from gold supervision; harvest coverage is, since self-sampling only reaches questions the zero-shot model can already solve. **C**, gold-program SFT, reaches **40.0%** — 7.3 points *above* its own supervision ceiling, with 34 of its correct answers on questions the translator could not express: trained on translatable shapes, it composes solutions for untranslatable ones, the compositional-generalisation signature of Chapter 9 reappearing in a foreign domain. Decomposition locates C's residual precisely: on the oracle-solvable subset it scores 85.3%, nine points from the executor ceiling, with residual errors split between field grounding (the majority), structure, and a negligible normalisation tail; intent misreading sits at the detector's noise floor. The typed-feedback reflector, significant for both zero-shot arms (+2.0 and +3.3 points, zero regressions), contributes nothing after SFT — replicating, in a new domain, the main pipeline's finding that repair value is a decreasing function of planner maturity.

## 11.3 One run on the sealed test

With the configuration frozen (1,000 steps, extended algebra, value linker, single call, guided decoding), pools rebuilt on train+dev under a pre-declared protocol amendment, and a manifest of commit hash and file checksums recorded, the pristine-unseen test set (4,344 questions) was run once and scored by the official evaluator:

| arm | official accuracy |
|---|---|
| base, zero-shot | 22.51% |
| procurement planner, zero-shot | 27.33% |
| **A-final: answer-only bootstrap** | **44.43%** |
| **C-final: gold-program SFT** | **51.80%** |

Every rung is decisively significant (McNemar p ≤ 5e-18). At test power the zero-shot gap between base and the procurement planner *is* significant — a +4.8-point weight prior that the 300-question dev set could not detect — so the portability claim is stated with its refinement: weights carry a small zero-shot prior; the recipe delivers the bulk, +17 points beyond the prior for answer-only supervision and +24.5 for gold programs. For calibration, 51.8% sits above the classic supervised semantic-parsing band on this benchmark and near early pre-trained table models, from an 8B local model with a closed verifiable algebra and 5.4k training examples; 44.4% — with no program supervision at all — matches classic fully-supervised parsers. The test set is now consumed: any further run on it is post-hoc by definition, and subsequent development reports dev-side numbers only.

## 11.4 Closing the representation gap without touching the algebra

The coverage boundary itself was then attacked under a discipline set in advance: a SQL-expression normalisation-and-lowering layer (IN-lists, BETWEEN, comparisons between aggregate subqueries — all lowered to *existing* nodes) and the typed loader views, evaluated by a four-way attribution audit — baseline, translator-only, loader-only, both — with a zero-regression gate. Coverage: 54.7% → 61.0% train, 52.7% → 60.1% dev, fidelity held, regressions zero, and the two modules recover disjoint question sets (562 translator-only, 154 loader-only, 14 jointly). The migration matrix gives the chapter its sharpest sentence: **about 14% of the apparent coverage gap was compiler-and-representation incompleteness, recovered with the algebra frozen; the remaining 86% concentrates in two genuinely missing semantics** — general expression predicates (field-versus-computed-value, ~13% of gold programs) and ordered-relation navigation (~5%) — specified as future type-system extensions (`Predicate⟨Expr,Expr⟩`; an `OrderedRelation` with explicit order provenance) rather than implemented ad hoc. The audit gate also caught three implementation bugs en route, each invisible to any merged accuracy number.

## 11.5 Migration cost and limitations

The full ledger: one loader (~150 lines), one evaluator adapter (~90 lines), one value linker (~60 lines), tooling (translator and audits, ~700 lines, none of it runtime), one generic operator, zero changes to the seventeen originals, and one GPU-day of light SFT end to end. Limitations: the consumed test set caps what future WTQ work can claim formally; the gold-program arm depends on Squall's annotation quality (its own ceiling is 89%); channel surfaces are crowd-written but the harvest pools inherit the planner's blind spots; and the two identified type-system extensions, with an estimated eighteen further coverage points behind them, are designed but deliberately unbuilt — they are the next thesis's first chapter, not this one's last.
