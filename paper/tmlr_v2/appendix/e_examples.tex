\section{Trace and Output Examples}
\label{app:examples}

\subsection{Direct compositional success and base failure}

For PACS item \texttt{PACS::F6:L3:f6\_other\_buyers\_via\_suppliers:0011\#a}, the question asks
which buyer-name values are connected through the lead suppliers of an anchor buyer, excluding
the exact anchor string.  The untuned model emits the following compressed computation:
\begin{verbatim}
VALUES contract_node_id [supplier_name = anchor]
  DIFFERENCE
VALUES contract_node_id [buyer_name = anchor]
\end{verbatim}
It reverses the role in the first filter and projects contract IDs, yielding the empty set.  The
typed-program model emits:
\begin{verbatim}
S = VALUES supplier_name [buyer_name = anchor]
B = VALUES buyer_name    [supplier_name IN_EXPR S]
A = B DIFFERENCE VALUES buyer_name [buyer_name = anchor]
\end{verbatim}
This item ran under the direct typed-program protocol, so the deployment understander, planner,
and release checks were not involved: it evidences semantic parsing and deterministic set
execution and nothing about the runtime.  The deterministic evaluator returns the 17 stored
strings in the oracle.  Representative values
are ``Ards and North Down Borough Council'', ``Leeds City Council'', and ``NI Water and its
subsidiaries''.  The output also contains organisation-name variants; it must be captioned as 17
stored buyer-name values, not 17 unique organisations.

\subsection{Unsupported sibling}

A separate F6--L3 control asks, ``What is the average number of buyers per supplier in this
scope?''  Average is outside the closed algebra.  The specialised model returns an explicit
abstention object with the reason that the operation is not expressible.  This is an independent
test item, not a failure branch of the answerable bridge question.

\subsection{Provenance of the introduction figure}

Figure \ref{fig:visual-thesis} is drawn from a single question,
\emph{How many contract notices were published by buyers who have awarded a contract to Edmundson
Electrical Limited?}, taken from the balanced comparison set with its template preamble removed.
Every panel was re-run under current code against the same graph snapshot, and the full bundle,
including retrieved records, emitted programs, and the runtime trace, is stored at
\path{data/qa/figures/fig1/fig1_trace.json} and regenerated by
\path{scripts/paper_figures/fig1_trace.py}.

Computing the denotation directly over $U_G$ gives 23 records naming the supplier, 16 distinct
buyer values, and 4{,}257 notices published by those buyers, which reproduces the frozen oracle.
The retrieval panel uses TF-IDF over the record projection at $k=40$ with field boosting and an
untuned Qwen3-8B reader; retrieval recovered all 23 first-hop records and the reader still
answered 14.  The unsupervised-program panel is the PACS single-decode protocol on the untuned
model: its tree passes static validation with root type \numbertype{} and executes to 23, because
it filters on the supplier anchor and counts the source records instead of bridging.  The
typed-program model emits the full bridge and executes to 4{,}257.

Two limits of the figure should be read with it.  The runtime panel was produced by the
deterministic rule-based planner: its stored trace records \texttt{llm\_role: planner\_only},
\texttt{planner\_version: rule\_based\_planner\_v1}, and the stage sequence \texttt{planner},
\texttt{pre\_execution\_review}, \texttt{grounding}, \texttt{retrieval},
\texttt{preflight\_verifier}, \texttt{kg\_executor}, \texttt{runtime\_verifier},
\texttt{evidence\_verdict}, \texttt{answer\_sanity}, \texttt{reflector}, \texttt{answer\_card}.
The learned understanding and planning stages shown in the figure therefore depict the runtime's
architecture and were not exercised for this item, because the Step-1 and Step-2 adapters are not
recoverable from the machine-specific artifact store (Section \ref{sec:limitations}).  The
evidence bundle also returns up to 200 identifiers rather than one per counted record, so the
displayed identifiers are a sample.
