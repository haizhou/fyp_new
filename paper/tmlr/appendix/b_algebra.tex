Base predicates are \texttt{eq}, \texttt{in}, \texttt{contains}, \texttt{exists},
\texttt{gte}, and \texttt{lte}.  \texttt{not} negates one predicate, \texttt{any} disjoins two
or more predicates, and \texttt{in\_expr} evaluates a \values child and applies membership or
negated membership to a field.  Numeric \texttt{combine} operators are \texttt{diff},
\texttt{ratio}, and \texttt{add}; Boolean comparisons are \texttt{gt}, \texttt{lt},
\texttt{ge}, \texttt{le}, and \texttt{eq}.  Set operators are union, intersection, and
difference.

The validator enforces compositional types, required arguments, a maximum depth of 16, a maximum
of 64 nodes, and $k\leq50$.  It does not restrict every field to the runtime schema and it does
not make the additivity or currency guard intrinsic to \texttt{sum}.  Those are separate domain
contracts.  Runtime failure modes include unknown fields, non-finite/non-numeric sums, no result,
and multiple distinct values for a scalar selection.  For \texttt{extreme\_rows}, all tied rows
at the extremum are retained; downstream scalar selection therefore fails on unresolved ties
instead of choosing an arbitrary row.

Counts and grouped counts deduplicate contract identifiers.  Projections return sorted distinct
non-empty strings.  Grouped keys exclude null and empty strings.  Numeric sums use decimal
accumulation before conversion to the JSON answer representation.  Ranking ties are broken
deterministically by the key string after the numeric score.
