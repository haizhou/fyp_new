\section{Discussion and Limitations}
\label{sec:discussion}

\paragraph{Overall finding.}
Deterministic checks support release and data selection but do not certify meaning.  The replay
isolates one successful aggregation guard, while the harvest and constraint audit show divergence
among runtime acceptance, oracle agreement, and constraint retention.  SFT is the only checkpoint
transition that improves both model families, and later stages are not monotonic.  The main
procurement comparison favours the full runtime, whereas PACS, WTQ, and the fixed planner use
narrower protocols.

\paragraph{Learning boundary.}
This training path is not an agent that improves itself autonomously.  Initial plans come from cloud
teachers, positive targets require an external oracle, and only the later harvest uses Step 2 plans
generated by the student.  Each checkpoint changes the corpus or objective, has one training run,
and lacks a matched unfiltered control.  The ladder therefore reports stored checkpoint changes
rather than a causal effect of checked execution.  The later neutral or adverse results remain
unexplained by the present experiments.  The evidence supports training under an oracle gate, not
recursive improvement.

\paragraph{Data truth boundary.}
Every factual claim is conditional on the frozen procurement snapshot.  Deterministic execution
can compute the declared query exactly while the source remains incomplete or historically
inconsistent.  Entity resolution prioritises precision and leaves some aliases separate, so projected names
are not guaranteed to be distinct legal organisations.  More than half of evidence edges use an
OCID fallback rather than an exact lot link.  Currency is stored without conversion, and some
additive rows are not GBP.  The monetary tasks therefore test the snapshot conventions rather than
certified totals outside the snapshot.  We did not run a controlled node, edge, or field deletion study, so
correct handling of declared no result questions is not evidence of robustness to an incomplete KG.

\paragraph{Verification boundary.}
The runtime separates learned proposal from deterministic value computation, but its release
decision has a defined scope.  It records grounded constraints, variable populations, and contract
identifiers.  Large answers retain the exact population count and only a bounded evidence sample.  The main result
files contain predictions rather than full traces, and no production document inspector verifies
source passages.  Citation precision and recall are therefore not reported.

Runtime verification also differs from semantic faithfulness.  An answer can match the oracle even
when a condition is redundant on the current snapshot and absent from the plan.  The targeted
repair audit demonstrates this possibility but does not estimate its prevalence across all model
outputs.  One implementation path makes the risk concrete.  A check after compilation may add a missing
year, CPV, or category to a flat query specification while execution still prefers an existing
graph plan without that condition.  The graph plan should be updated, or the modified specification
should be recompiled, before this check can serve as a guarantee.  Online repair is triggered by
runtime checks rather than the answer.  Only a structured repairable failure permits another
proposal.  States judged to be clean empty results, ambiguous, or unsupported terminate.

\paragraph{Reproducibility boundary.}
Two exact question and answer strings and five deduplication groups cross the train and evaluation
boundary.  PACS also uses a sampled trigram screen and contains two overlaps between Compose-v3
train and validation.  Removing the development subset containing 260 items cannot undo earlier
design choices informed by diagnostics.  The final WTQ C training snapshot and complete command and
checkpoint manifests are missing.  Single training runs and different serving stacks further
prevent estimates of seed and infrastructure variance.

\paragraph{Responsible use.}
The system supports exploration and audit of complete counts, set relations, extrema, and patterns
involving multiple hops across buyer and supplier relations under a declared data snapshot.  It
should not support automated allegations, supplier ranking, or procurement decisions.  A released answer should carry the data
snapshot, query conventions, population count, provenance sample, and known limitations.  This
information states where deterministic authority ends and where human source review remains
necessary.
